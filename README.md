# 月ごとの共有プランナー

1か月の日付ごとに、1コマ目・2コマ目・備考を共有する小規模Webアプリです。通常URLは閲覧専用、`?edit=1` は編集者名とPINで編集できます。

公開URL: https://month-planner-13f9a0.netlify.app/

月間表示・PIN編集・取り込んだ時間割を収録しています。PCは月間／2週間の日曜〜土曜の7列カレンダー、スマートフォンの月間表示は、1日を含む週から末日を含む週まで日曜始まりで数えた週番号の選択ボタンと、選択週から2週分の日付一覧で予定を確認できます。2週間表示は週番号の選択ボタンを表示せず、14日すべてを一覧に表示します。選んだ週と翌週を14日表示します。月間は月初を含む週の前週から月末を含む週の翌週まで表示し、隣接月の日付と予定も共有します。週ボタンは開始週だけを「1週」「2週」のように表示し、先頭の前月の週だけ「9月4週」のように月を付けます。選択週と翌週の14日を表示し、読み上げラベルには「9月4週/10月1週」のように2週の組と日付範囲を保持します。隣接月の日付は月/日と破線で示します。表示中の2週目の日付を選んでも週番号の選択は変わりません。PCでは各日の先頭行に日付と固定時間割を並べ、追加見出し・備考はその下に表示し、セル内の内容を上揃えにします。日付を選ぶと下に詳細を表示します。編集用PINはNetlifyの環境変数 `EDIT_PIN` で管理し、リポジトリへ保存しません。

Netlify FunctionsとNetlify Blobsを使用します。初期表示は今月です。月間は前月・翌月、2週間は日曜始まりの14日間を前後へ移動できます。「今日」で現在の期間へ戻ります。詳しい仕様は[DESIGN.md](DESIGN.md)、ページとファイルの対応は[SITEMAP.md](SITEMAP.md)を参照してください。

## 使い方

画面上部は取説・編集の操作だけを表示し、ブランド・ページ見出し・説明文の縦幅を省いています。

ヘッダー付近の「文字」で標準・大・特大を選べます。本文・入力・カレンダー・取説の文字が拡大され、選択をこのブラウザへ保存します。保存できない環境でも当ページの切替は利用できます。リンクと操作ボタンはコンパクトなボタン表示です。

ヘッダーの「取説」または `/#help` でSPA内の取説を表示します。編集URLは `/?edit=1#help` のまま利用できます。「カレンダーへ戻る」とブラウザの戻る・進むで移動でき、認証・選択日・入力・JSONプレビューを保持します。取説への移動でフォームを送信しません。備考の自動保存と同期は継続します。

通常URLで閲覧し、`?edit=1` で編集者名とPINを入力します。午前・午後の編集ボタンから見出し・内容をダイアログで入力し、「保存」で共有します。時間割の科目は読み取り専用です。備考は入力から500ms後に保存され、他の端末には3秒ごとの読み込みで反映されます。通信失敗時は入力を保持し、再試行できます。

ダイアログの「キャンセル」、閉じるボタン、Escapeで保存せず戻れます。通信失敗時は入力を保持し、保存を再試行できます。認証切れはダイアログ内でPINを入力し直します。見出しは120文字、内容・備考は3000文字以内です。通常のPIN編集では時間割設定の変更はできません。既存のJSONスキーマ・予定データは保持し、移行や削除は行いません。

追加予定は編集画面の「JSON取込」から貼り付けるかファイルを選び、「検証・プレビュー」で更新値を確認して取り込みます。[追加予定の雛形](public/entries.example.json)を利用できます。日付と午前・午後の見出し・内容、備考だけを指定でき、固定時間割は変更しません。指定項目の既存値は更新され、省略項目は保持されます。空文字はその欄を空にします。最大31日、重複日付不可、256KiB以内、見出し120文字、内容・備考3000文字です。未保存の日別入力を保存してから取り込んでください。部分失敗は日ごとの保存済み・未保存を確認し、入力を保持したまま再試行できます。同じ値の再送で履歴は増えません。

[農林の取込JSON](public/nourin-base.json)は、[農林カレンダー](https://nourin.honya.dev/)の2026年10月・野菜／有機コースA班のみです。2026-10-05に配信中の `assets/index-KbOb2MuM.js` から科目と休日を取得しました。午前の実習が全日扱いで午後が省略されている日は、元サイトと同様に午後にも実習を反映しています。自動追従ではなく、この時点の取り込みです。

## 検証

Node.js 22.12以上で実行します。

```sh
npm ci
npm test
npm run check
```

テストはPIN検証、入力制限、日付・月境界、JSON設定、別セルの同時更新、履歴記録失敗と回復を対象にします。SDKのローカルBlobsServerはGET応答のETagを欠くため、API全体のSDK結合テストはこの条件を検出した場合にスキップします。条件付き書き込みのSDK契約とAPIの競合制御は別のテストで確認します。Netlify本番の接続確認は別途必要です。

変更前のSH-53A実機で月間7列、2週間7列×2段のカレンダー表示・切替と、日付選択による詳細切替を確認済みです。IME入力と実データの保存は未検証です。

実環境の同時更新後の読み取り整合性は[後続Issueの本文](docs/concurrency-issue.md)へ切り出しています。更新消失は未確定であり、今回のデプロイ準備の完了条件からは外しています。

## Netlifyへの公開

GitHubリポジトリは `hogehonya/month-planner` です。NetlifyでこのリポジトリをImportします。`netlify.toml` に公開先 `public` とFunctionsディレクトリ `netlify/functions` を定義しているため、ビルドコマンドは不要です。

Netlifyの環境変数に `EDIT_PIN` を設定し、Functionsから利用できるようにしてデプロイします。値はソース・URL・公開ファイルへ記載しません。`.env.example` にも実値は入れていません。PINが未設定の場合、閲覧APIは動作しますが編集は拒否されます。

公開後は通常URLで閲覧、`?edit=1` で認証・保存、別端末で同期、コマの見出し・内容と履歴を確認してください。データはサイト単位のBlobsストアに保存します。同じサイトへの再デプロイで維持されます。

このアプリは少人数向けの簡易PIN認証です。URLを知る人は予定と編集者名・履歴を閲覧できます。自動バックアップやアカウント管理はありません。

## 日付ごとのコメント

選択日のコメントは通常URLから読めます。`?edit=1` で既存の編集者名とPINを認証し、3000文字以内のコメントを追加できます。投稿者と投稿日時も公開されます。コメントは追加のみで、編集・削除はありません。通信失敗時は入力を保持し、同じ投稿を再試行できます。未送信のコメントがある間は日付・期間の移動とJSON取込を止めます。

## 荷姿写真マスタ（Issue #35）

`/packaging.html` は品目とSKUを分けて表示します。品目は指定の24品目です。既存20品目のID `item-01`〜`item-20` を保持し、共有表にあるエダマメ・トマト（大玉）・キャベツ・ショウガを `item-21`〜`item-24` として追加します（Issue #45）。SKU ID・SKU名・品種／種類・栽培方法（有機／慣行）・価格（円）・荷姿条件・荷姿写真・備考をSKU単位で登録します。栽培方法・価格・荷姿条件は任意項目で、不明な値は未確認・空欄のまま登録できます（Issue #41）。栽培方法はトグルのONで有機、OFFで慣行を選びます。未確認は別の表示で保持し、「未確認に戻す」で戻せます。新規SKUは未確認から開始し、切り替えず保存すると未確認を保持します（Issue #43）。価格は0以上の整数円、荷姿条件は3000文字以内の自由記述です。未入力価格は0円と区別します。既存SKU・写真は維持します。2026-10-06のユーザー要求「登録して、有機と慣行と」に基づき、共有表の品目・品種と栽培方法をSKU単位で登録します（Issue #45）。表で品種が不明の行も品種欄を空欄にして仮登録し、栽培方法が不明なら未確認を保持します。未指定の価格・荷姿条件は空欄とし、品種名・写真を推測で補いません。既存のサンプルSKUは保持します。登録データはAPIで共有ストアへ保存し、リポジトリに取込データやseedは追加しません。

登録手順は「品目を選ぶ → SKU・写真を保存」の2枚のカードで示します。スマートフォンでは品目カードを2列で表示し、SKU登録済みの品目は写真・商品情報を読みやすくするため全幅で表示します。各品目カードの「登録」は常に表示し、選択した品目の登録フォームを直接開きます。SKU IDには既存の商品管理コードを入力し、コードがない場合は自分で重複しない英数字のIDを決めます（入力例を表示）。IDの自動生成や架空のSKUの追加は行いません。

閲覧・追加・編集はPINなしで利用できます。プランナーの `EDIT_PIN` 認証は引き続き必要です。写真はJPEG・PNG・WebP、3MiB以内で、サーバーでもサイズと形式の署名を検証します。写真を選択しない編集は既存写真を保持します。SKU IDは登録後変更できません。通信失敗は入力を保持し、競合は再読込して確認します。

Functionsの `packaging` APIと、同一Netlifyサイトの独立した `packaging-master` BlobsストアにSKUと写真を保存します。再デプロイ後も保持し、プランナーのストア・予定は変更しません。SKUはETagで条件付き保存します。写真更新時は別の写真IDへ保存し、以前の写真は保持します。SKU・写真の削除、品目の編集、写真の自動圧縮は今回の対象外です。公開後の実写真アップロードと別端末からの閲覧は本番確認が必要です。
